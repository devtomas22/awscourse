Summary

  • Shared responsibility (2.1). AWS secures of the cloud — physical facilities, hardware, hypervisor, and network; you secure in the cloud — your data, identities, configuration, and patching. The split shifts with service type: on EC2 you patch the guest OS; for RDS and Lambda, AWS patches the engine and runtime.
  • Root user is an emergency key (2.3). The email-tied root identity can close the account, change the account email/contact info, and restore IAM user permissions — a short list. Protect it with MFA, give it no access keys, and do daily work in IAM identities instead.
  • Least privilege everywhere (2.3). Grant only what is needed: scoped policies on groups and roles, passwords meeting the account policy, access keys only when required, and IAM roles handing workloads temporary credentials. Identity Center (formerly Single Sign-On) federates your directory across accounts.
  • IAM evaluation is deterministic: an explicit deny always wins; with no matching allow there is implicit deny nothing — access exists only because a policy grants it.
  • Encrypt by default, prove the basics (2.2). Data in transit moves over TLS; data at rest is encrypted by KMS-managed keys — and every new S3 upload is already encrypted with SSE-S3 before you touch a setting.
  • Audit trail vs configuration trail (2.2). CloudTrail answers “who did what, from where, when” (90-day event history; trails for more); Config records how resources were configured and whether that stayed compliant.
  • Detect, scan, protect (2.2/2.4). GuardDuty ML-detects threats from CloudTrail, VPC flow logs, and DNS logs; Inspector scans EC2/ECR/Lambda for software vulnerabilities; Macie finds PII in S3; Security Hub aggregates all findings against standards.
  • Compliance is self-service (2.2). AWS Artifact hands you SOC/PCI-type reports and agreements on demand; requirements vary by geography and industry, so the exam ties compliance needs to region/sector answers.
  • Edge defense in two pieces (2.4). WAF filters layer-7 web requests with managed rule groups on a web ACL; Shield absorbs DDoS — Standard is free and automatic, Advanced adds paid protections for critical workloads.
  • Exam framing: Domain 2 is 30% of scored content — second only to Domain 3. Shared-responsibility questions are practically guaranteed; know the shift pattern and the only-root list cold.

Main concepts

Four clusters — access, audit, detection, compliance — each mapped to Domain 2 task statements.

The shared responsibility model, precisely
AWS: facilities, hardware, hypervisor, managed runtime internals. You: data classification, IAM, encryption choices, guest OS patches, network settings. Exam trick: name which half each action belongs to — patching a Lambda runtime is AWS’s; patching your EC2 AMI is yours.
Root user: what only it can do
Sign in as root only for the short task list the docs maintain: close the AWS account, change the account email/contact info, restore IAM user permissions, and a few account/seller settings. Elsewhere use IAM identities. Protections: MFA on root, no root access keys, delegation via IAM users/roles or Identity Center.
IAM building blocks under least privilege
Users get passwords/access keys; groups hold shared policies; roles grant temporary STS credentials a workload assumes; policies are Effect/Action/Resource JSON. Least privilege = narrowly scoped policies and role-based access, never wildcard-broad grants out of convenience.
Policy evaluation: deny wins, allow required
Requests start denied (implicit deny). A matching allow grants unless a matching explicit deny exists — and explicit deny outranks every allow. That one rule decides half the exam’s IAM questions.
Identity Center and federation
AWS IAM Identity Center (formerly AWS Single Sign-On) centralizes workforce access — users sign in once with corporate-directory identities (federation) and get assigned permissions across accounts, instead of cloned IAM users.
Encryption: in transit, at rest, and who holds keys
In transit: TLS everywhere. At rest: server-side options on every service — S3 alone offers SSE-S3, SSE-KMS, and customer-provided SSE-C — with KMS key policies controlling use and CloudTrail logging key usage. S3 encrypts every new object automatically with SSE-S3.
CloudTrail vs Config: action log vs settings log
CloudTrail: API-call audit — action, identity, source IP, time; console event history covers 90 days of management events, and trails deliver a durable record. Config: resource configuration over time with rule-based compliance evaluation. Together: who did what + what the resource looked like.
The detection lineup — who watches what
GuardDuty: ML over CloudTrail management events, VPC flow logs, and DNS logs → threat findings. Inspector: scheduled vulnerability scans of EC2, ECR images, and Lambda. Macie: sensitive-data discovery (PII) across S3. Security Hub: consolidated findings plus security-standard checks. Exams map each to its input data.
Compliance reporting with Artifact
AWS Artifact = self-service portal: download AWS and ISV compliance reports (SOC, PCI) and review/accept agreements yourself. When a scenario needs audit evidence, Artifact is the answer. Audit Manager complements it by collecting internal evidence mapped to control frameworks.
Edge protection: WAF and Shield
AWS WAF inspects web requests at layer 7 using rules (including managed rule groups) assembled on a web ACL. AWS Shield counters DDoS: Standard is automatic and free on AWS; Shield Advanced is the paid tier for larger attack surfaces. Marketplace also sells third-party security tooling.
Secrets: rotation vs storage
Secrets Manager: stores secrets and rotates them on a schedule (DB credentials, API keys, OAuth tokens). SSM Parameter Store: hierarchical configuration values; SecureString type encrypts with KMS — a lighter-weight, cheaper store for static config.
Where security information lives
Docs, the AWS Knowledge Center KB articles, the AWS Security Blog, and compliance programs mapped on the AWS Compliance pages; Trusted Advisor flags basics like open security-group ports and missing root MFA in its core checks.

Flashcards

40 cards — click a card to flip it to the definition.

Shared responsibility model
AWS secures of the cloud (facilities, hardware, hypervisor, network); you secure in the cloud (data, identities, configuration, guest OS).
Security OF the cloud
AWS’s half: physical data centers, hardware, the hypervisor, and the global network plumbing nobody else can reach.
Security IN the cloud
Your half: protecting data, IAM users/policies, encryption choices, guest OS patches on IaaS, and your network configuration.
Responsibility shifts with the service
The more managed the service, the more AWS covers — EC2 leaves OS patching to you; RDS and Lambda patch their engine/runtime themselves.
Customer responsibilities
Data and its classification, IAM users/roles/policies, enabling encryption, guest OS patching, application security, and network firewall choices.
AWS responsibilities
Physical security, hardware upkeep, hypervisor isolation, and managed-service internals (patching RDS engines, protecting underlying storage).
Who patches what
EC2 guest OS: you. RDS database engine + its OS and Lambda runtime: AWS. The exam’s favorite shared-responsibility question.
Data classification stays yours
AWS secures the storage after upload; labeling sensitivity and choosing protections remains a customer responsibility.
AWS account root user
The email-tied identity with account-wide power: use only for the root-only task list, protect with MFA, keep no access keys.
Root-user-only tasks
Only root can close the account, change the account email/contact info, and restore IAM user permissions (plus a few account/seller settings).
MFA
Adds a hardware or virtual TOTP device on top of the password — enable it on root and IAM users first.
IAM users
Identities for people or long-running needs, carrying credentials (password, access keys) plus permissions from attached policies.
IAM groups
Attach a policy once and apply it to many users through membership — cleaner least-privilege management.
IAM roles
Temporary credentials via STS: workloads or federated people assume a role for short-lived access — roles are assumed, never signed into.
IAM policy
A JSON document of Effect/Action/Resource statements attached to users, groups, and roles (or resources) that decides what can act on what.
Explicit deny (IAM evaluation)
The strongest vote in IAM evaluation: any matching explicit deny beats every allow.
Implicit deny
No matching allow = no access. IAM permits nothing unless a policy grants it.
Least privilege
Grant only what the task needs: scoped policies, groups for shared rights, roles for workloads — no wildcard grants for convenience.
Access keys
Long-lived CLI/API credentials: create sparingly (root keys only if required), store securely, rotate, and prefer roles for automation.
Password rules (account-wide)
Account-wide rules — length, complexity, rotation — that every IAM user password must satisfy.
IAM Identity Center
Formerly AWS Single Sign-On: one sign-in for workforce identities with permissions assigned across accounts; federates your corporate directory.
Cross-account IAM role
A principal in one account assumes a role in another — the standard pattern for sharing access without cloning users.
AWS CloudTrail
The API audit log: which identity did what, from which IP, when. Event history covers 90 days of management events; trails keep a durable record.
AWS Config
Records resource configurations over time and evaluates them against compliance rules — the settings trail, not the action trail.
Amazon GuardDuty
ML threat detection over CloudTrail management events, VPC flow logs, and DNS logs — turns unusual activity into findings.
Amazon Inspector
Automated vulnerability scanning of EC2 instances, ECR container images, and Lambda functions — software CVEs and network exposure.
Amazon Macie
ML plus pattern matching that discovers PII and other sensitive data across your Amazon S3 estate.
AWS Security Hub
One consolidated pane aggregating security findings across services and accounts, evaluated against security standards.
AWS Artifact
Self-service portal for AWS/ISV compliance reports (SOC, PCI) and for reviewing and accepting compliance agreements.
AWS Audit Manager
Collects evidence from settings and usage and maps it to control frameworks into audit-ready reports.
AWS KMS
Managed key service: creates and secures encryption keys, powers envelope encryption, enforces key policies; auto-rotates customer-managed symmetric keys on a yearly default.
AWS Secrets Manager
Stores secrets (DB credentials, API keys, OAuth tokens) with automatic rotation schedules.
SSM Parameter Store
Hierarchical configuration storage; the SecureString type encrypts values with KMS — lightweight static config + secrets.
AWS WAF
Layer-7 web firewall: rules (managed rule groups included) on a web ACL filter malicious web traffic before it reaches apps.
AWS Shield
DDoS protection: Standard is automatic and free on AWS; Shield Advanced is the paid tier for critical workloads.
Encryption in transit
Data moving is protected with TLS — every AWS service endpoint speaks HTTPS; credentials never travel in the clear.
Encryption at rest
Stored data encrypted by server-side options (S3’s SSE-S3/SSE-KMS/SSE-C) or client-side before upload, with KMS managing keys.
S3 default encryption
Every new object upload is automatically encrypted with SSE-S3 managed keys at no extra cost — default behavior, not an add-on.
Trusted Advisor (security)
Flagged basics in its core checks: open security-group ports, public snapshots, missing root MFA.
ACM certificates
TLS certificates provisioned and kept renewed for your domains — public certificates at no charge, so HTTPS stays on by default.

Quizzes

Pop quiz drills the Domain-2 task statements; real-world picks map situations to the right service; the security-tool drill pairs each job with its service — first try counts.

1. Walk through the shared responsibility split for EC2 versus RDS versus Lambda — who patches what?

Show answer
You patch the guest OS on EC2. For RDS, AWS patches the database engine and its OS while you handle data, accounts, and network settings. For Lambda, AWS runs and patches the runtime — you own only code and configuration. That shift-with-service pattern is the core Domain 2 fact.

2. A teammate uses the root account for everyday work. What should change?

Show answer
Stop using root day-to-day: enable MFA on root, delete root access keys, create IAM identities or Identity Center users for the team, and sign in as root only for the short root-only list (close account, change account email/contact, restore IAM user permissions).

3. An auditor needs proof that AWS itself meets SOC and PCI expectations — where does that come from, without a support ticket?

Show answer
AWS Artifact: the self-service portal for compliance reports (SOC, PCI) and agreements. Bonus point: Audit Manager collects your own internal evidence for your side of the audit.

4. Which two services together answer “who did what” and “what did the resource look like” — and what are their windows?

Show answer
CloudTrail logs API actions (identity, IP, time) with a 90-day console event history; trails extend that. Config records resource configuration over time with compliance evaluation. Action trail vs settings trail.

5. The CISO wants ML threat detection over account activity. Which service reads CloudTrail, VPC flow logs, and DNS logs?

Show answer
Amazon GuardDuty. It machine-learns over those exact sources and produces findings; findings can funnel centrally into Security Hub.

6. A workload needs AWS access. Compare access keys, passwords, and roles — and state the one rule of policy evaluation.

Show answer
Long-lived access keys for CLI/API only when required; passwords + MFA for console users; roles give workloads temporary STS credentials without stored secrets. In evaluation, an explicit deny beats any allow, and nothing is available without an allow.

1. The audit team asks for this quarter’s SOC and PCI evidence, today.

Show answer
AWS Artifact — download the reports and accept any agreements self-service, no ticket needed.

2. Thousands of S3 buckets; nobody knows where customer PII landed.

Show answer
Amazon Macie — ML and pattern matching discover and report sensitive data across the S3 estate.

3. You want weekly automated CVE scanning of EC2, container images, and Lambda functions.

Show answer
Amazon Inspector — scans exactly those targets for software vulnerabilities and unintended network exposure.

4. Security ops suspect compromised credentials making unusual API calls.

Show answer
Amazon GuardDuty — ML over CloudTrail management events, VPC flow logs, DNS logs produces threat findings; pipe them into Security Hub for one pane.

5. A public app is being hammered: malicious web payload patterns plus a DDoS flood on launch day.

Show answer
AWS WAF for layer-7 payload filtering (managed rule groups on a web ACL) with AWS Shield absorbing the DDoS — Standard is already free and automatic.

6. Engineers keep static app config in env files and DB passwords in scripts.

Show answer
SSM Parameter Store (SecureString, KMS-encrypted) for static config, and Secrets Manager where credentials need scheduled automatic rotation.
