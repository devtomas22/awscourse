Day 2026-10-22 · EC2 Compute Fundamentals

Pluralsight: AWS Compute Fundamentals — the EC2 module: which workloads belong on EC2, launching and connecting (SSH, RDP, Session Manager), the instance lifecycle, and where EC2 sits on the AWS compute spectrum.

Day 2Topic: EC2Source: Pluralsight + class notes

Summary

Today was the AWS Lambda fundamentals day:

  • What Lambda is — serverless compute — you upload a function (code + handler + config) and AWS runs it on demand: no servers to provision, patch, or size, and it scales from a few calls a day to thousands a second.
  • Invoking it — three modes: synchronous (caller waits — API Gateway, CLI), asynchronous (queue + retries — S3, SNS, EventBridge, SES) and event source mappings (Lambda polls Kinesis / DynamoDB streams / SQS and delivers record batches). EventBridge adds cron schedules; Function URLs give a direct HTTPS endpoint.
  • Sizing & limits — memory 128 MB–10,240 MB, and CPU scales with memory (one full vCPU at 1,769 MB); per-invocation timeout — default 3 s, cap 900 s (15 min); payloads 6 MB sync / 1 MB async.
  • Billing — requests (~$0.20 per million) + duration in GB-seconds — nothing while idle; free tier 1M requests + 400,000 GB-seconds every month.
  • Packaging & versions — runtimes from Node.js/Python/Java to custom; .zip (250 MB unzipped) or 10 GB container images; up to 5 shared layers; immutable versions with $LATEST head, alias pointers (PROD), 4 KB of environment variables.
  • State & spectrum — stateless — state lives in S3/DynamoDB/DBs, /tmp is scratch only; per the compute-spectrum it's the restaurant: operational burden traded for constraints (15-min ceiling, memory cap, managed runtime) — exactly the counterpoint to EC2's cook-at-home.

Main concepts

What is AWS Lambda
Serverless compute: run code without provisioning or managing servers. The function is the deploy unit — code plus handler plus configuration (memory, timeout, role). AWS owns the fleet, the OS, patching, and scaling.
Three invocation modes
Sync — the caller waits for the response (API Gateway, CLI, SDK). Async — Lambda queues the event, returns immediately, retries twice on failure, then routes the failure to a destination or DLQ (S3, SNS, EventBridge call this way). Event source mappings — Lambda itself polls Kinesis/DynamoDB streams/SQS and invokes the function with record batches (batch size up to 10,000).
Sizing: memory is the lever
You set memory 128 MB–10,240 MB in 1-MB steps; CPU scales proportionally — one full vCPU at 1,769 MB. There is no direct CPU knob: tune CPU through memory. Timeout per invocation: default 3 s, capped at 900 s (15 minutes).
Concurrency & scaling
Concurrency = simultaneous in-flight executions. Each concurrent request gets its own execution environment. Default quota: 1,000 per region (soft, raisable); a function can reserve part of it (default reserve cap 900, with 100 kept for unreserved functions). When the pool is dry, calls throttle.
Cold start vs warm
A cold start is the setup latency of a fresh environment: fetch the package, boot the runtime, run init code, then handle the first event. Warm calls ride environments already up — AWS reuses them when traffic allows. Fixes: SnapStart (Java: initialized runtime snapshotted and restored on demand) and provisioned concurrency (pre-warmed environments, billed even when idle).
Pricing — only while it runs
The whole bill is requests + duration: ~$0.20 per 1M requests plus per-GB-second of run time (memory × seconds). Nothing for idle — no parked servers. Free tier: 1M requests + 400,000 GB-seconds per month, permanently (not a 12-month trial).
Stateless — and where state lives
Between invocations Lambda keeps nothing; persist state outside the function: S3, DynamoDB, a database. /tmp is scratch (512 MB default, up to 10,240 MB) — reused while the environment is warm, never guaranteed. Invocation output lands in CloudWatch Logs.
Runtimes, packages, layers
Managed runtimes: Node.js, Python, Java, Go, .NET, Ruby — or a custom runtime for anything else. Code ships as a .zip (≤ 250 MB unzipped incl. layers) or a container image (≤ 10 GB, stored in ECR). Layers share libraries across functions (up to 5 attached).
Versions, aliases, env vars
A version is an immutable snapshot of code + config; $LATEST is the mutable head. An alias is a named pointer at a version (PROD → v7) — repoint it and callers never change URLs. Environment variables (4 KB total) configure behavior without redeploying.
The permissions model
Execution role — the IAM role the function assumes; its policies decide what the CODE may call (e.g. write to S3). Resource policy — attached to the function, names who may INVOKE it (services, other accounts); the Principal element lives here. Both must line up.
Event-driven glue
Typical triggers: S3 uploads (async), DynamoDB/Kinesis streams (mapping), SQS queues (mapping), EventBridge schedules (cron), HTTP (API Gateway sync or Function URL direct). The handler receives the event payload (JSON — the S3 event, the API request, or the record batch) plus a context object (remaining time, request ID).
Where Lambda sits (day 22 tie-in)
On the compute spectrum: Lambda = the restaurant — never see the kitchen, pay per plate, not per stove-hour. The trade: operational burden for constraints — 15-minute ceiling, memory cap, managed runtime, no OS control. Long runs, GPUs, kernel control, or steady always-on load → that's EC2's ground.

Java-focused cold-start fix: the runtime initializes up front, gets snapshotted, and is restored on demand.

Pre-warmed environments standing by so traffic never pays cold-start latency — billed even while idle.

vCPU rule
CPU is not set directly — it follows memory: 1,769 MB buys one full vCPU.
Payload caps
6 MB for a synchronous request or response; 1 MB for asynchronous.
Environment variables
Key/value config in the function settings (4 KB total) — changed without touching the code.
Version
An immutable snapshot of the code + configuration; $LATEST is the mutable head that publishes them.

Layer
A separately versioned zip of libraries/assets shared across functions — up to 5 attached.

The code artifact: unzipped size ≤ 250 MB including layers; 50 MB if uploaded directly.
Container image
Code + runtime packaged as an ECR image, up to 10 GB — when dependencies outgrow a zip.

A built-in dedicated HTTPS endpoint that invokes the function directly — no API Gateway needed.
Event payload
The JSON the trigger delivers: an S3 object event, an API request, or a batch of queue/stream records.
Context object
Runtime info handed to the handler each call: remaining milliseconds, function name, request ID.
Idempotency
Design so duplicated events don't double-write: async retries and stream re-delivery can repeat work.
CloudWatch Logs
Where each invocation's output lands — Lambda's default debugging trail.
Recursive loop
A function triggering itself through chained services; Lambda detects and stops Lambda↔S3/SQS/SNS loops.

Quizzes

1. In one sentence — what is AWS Lambda?

Show answer
Serverless compute: you upload a function and AWS runs it on demand — no servers to provision, patch, or size, scaling handled for you.

2. How is a Lambda function billed?

Show answer
Requests (~$0.20 per million) plus duration in GB-seconds (memory × run time). Nothing while idle; free tier: 1M requests + 400,000 GB-seconds monthly.

3. Name the three ways code gets invoked.

Show answer
Synchronous (caller waits — API Gateway/CLI), asynchronous (queued with retries — S3/SNS/EventBridge), and event source mappings (Lambda polls Kinesis/DynamoDB streams/SQS).

4. How big can a function be — memory and time?

Show answer
Memory 128 MB–10,240 MB (CPU scales with it — 1 vCPU at 1,769 MB); timeout default 3 s, max 15 minutes per invocation.

5. Cold start, warm start, init — the story?

Show answer
A fresh environment runs init (fetch package, boot runtime, init code) before the first event — that setup latency is a cold start. Warm calls ride reused environments. Fixes: SnapStart (Java) and provisioned concurrency.

6. Where does Lambda keep state?

Show answer
Nowhere — it's stateless. Persist to S3, DynamoDB, or a database; /tmp is scratch only, never guaranteed.

7. How do versions and aliases fit day-to-day deployment?

Show answer
Versions are immutable snapshots ($LATEST is the head); aliases are named pointers (PROD → v7) — repoint the alias and callers keep working.

8. Which IAM pieces govern Lambda — code-to-AWS and caller-to-function?

Show answer
The execution role decides what the code may call; the resource-based policy names who may invoke the function (Principal lives there).

9. Give four example triggers and their mode.

Show answer
S3 upload (async) · SQS queue (mapping) · Kinesis stream (mapping) · EventBridge cron (schedule) · API Gateway HTTP (sync) · Function URL (direct HTTPS).

10. On the compute spectrum, what does Lambda trade?

Show answer
Operational burden for constraints — it's the restaurant: no kitchen, pay per plate. Constraints: 15-min ceiling, memory cap, managed runtime, no OS control.

1. An image lands in S3 and needs a thumbnail. Mode and trigger?

Show answer
S3 event notification → asynchronous invocation: Lambda queues the event, generates the thumbnail, S3 never waits.

2. A report must run every night at 02:00 — without running a server.

Show answer
EventBridge schedule (cron/rate) invokes the function — pay nothing the other 23 hours.

3. A queue bursts to 10k messages/second — what protects you?

Show answer
The SQS event source mapping buffers and scales environments against it; watch the 1,000-per-region concurrency (raise the quota or reserve concurrency per function).

4. A 10-minute-high video transcode — still a Lambda job?

Show answer
No — it blows past the 15-minute cap; use ECS on Fargate or EC2 for longer runs.

5. A slow Java API endpoint feels the cold start at traffic peaks. Two fixes.

Show answer
SnapStart (initialized runtime snapshot/restore) or provisioned concurrency (pre-warmed, billed while idle).

6. A simple webhook API needs HTTPS today. Fastest route?

Show answer
A Function URL — dedicated HTTPS endpoint, direct invocation; add API Gateway only when you need path routing, keys, throttling.

7. A fleet of five identical instances (day 22) versus one function — who scales harder, and why?

Show answer
The function: Lambda starts more execution environments on demand per concurrent request — no fleet to provision; EC2 scales by adding instances you size yourself.

8. Duplicate async events are double-writing rows. What do you fix?

Show answer
Make the handler idempotent — dedupe on the event's ID before writing; retries/re-delivery are a feature, not a bug.
