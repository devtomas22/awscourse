Summary

  • A good prompt is a multiplier, and the difference between okay and perfect output is the phrasing, not the model. Three traps produce the giant useless ball of text: vagueness (a broad ask covers everything and says nothing), people-pleaser bias (a leading question gets confident agreement with a flawed premise), and overload (business plan + marketing + website copy in one prompt → three shallow lists).
  • Models read prompts as tokens — chunks of text from a vocabulary in the tens of thousands — and generate by repeatedly predicting the most likely next token. Vague or misleading input invites hallucination (confident fill-ins that are not true) and the sycophancy effect; clean, specific setup leads to relevant next words. Hallucination fixes the course names: ask for honesty (“if you are not sure, say so”), restrict the answer to provided material, request citations, keep the task scoped.
  • Context management: the model has no memory — the app re-sends the whole thread inside a limited context window; past the limit input is dropped, and big prompts degrade answers even before it. Long threads get opened fresh or summarized by providers; the fix on your side is chunking (summarize → then draft the email → then the captions) and instruction order — important words first, one task per turn.
  • Efficiency is part of the skill: APIs bill per token, input plus output, so skip preambles and overlapping instructions, set word limits, request bullet lists or tables, and ask for a summary first. Watch the provider dashboard, treat prompt performance like an A/B-tested feature, use caching where the API supports it, and monitor with PromptLayer, Langfuse, or Helicone.
  • Strategies are repeatable: the Act-as persona hack plus the formula — role, task, style, constraints; iterative refinement shapes output in small specific steps and reuses earlier answers as material; prompt chaining lets one model write the detailed prompt that another tool then executes.
  • Debug prompts like a system: isolate (drop 4 of 5 instructions, find the failing part), adjust (temperature — low for factual, high for creative — or metaprompting when the app gives you no dial: “entirely factual, no speculation” vs “take risks, give three varied options”), then self-correct (ask for the plan first; tell the model it failed, why, and regenerate).
  • Reasoning patterns: Chain of Thought ("think step-by-step") buys reliability where the process matters — math, logic, abstract tasks — but adds nothing for a single fact. ReAct interleaves reasoning with actions (thought → action → observation loop, the surrounding system executes the tool), bringing fresh grounded context in; it is the architectural blueprint behind AI agents, with parsable output and fewer hallucinations.
  • Generation and enterprise practice: image/video prompts follow subject + style + environment + parameters (MidJourney --ar/--seed/stylize/--chaos, four variations then upscale, negative prompts, style calling, reverse image prompting). Coding assistants: supply the relevant files or UI images, reuse prompt files, keep Git and human review as the safety nets, let the agent run the build to see errors, mind premium-request quotas, switch models when stuck. APIs: demand structured JSON with few-shot format locks, cache repeats, run deterministic settings (low temperature, fixed seeds), version prompts in Git, log telemetry, mask sensitive data. Ethics: representation, confirmation, and cultural bias (the Amazon recruiting-tool case), prompt injection; guardrails in three layers — the vendor's RLHF foundation and model spec, a context firewall that sanitizes data before the model, and a bias buffer designed into the prompt — plus red teaming.

Main concepts

Why prompt quality matters
The same task solved with one clean prompt replaces several clumsy back-and-forths — the improvement compounds across work, school, creative projects, and code. The gap is the phrasing, not the model: sharp prompts set the goal, audience, and format, so the output gets personality, relevance, and usable structure instead of a generic copy-paste answer.
The three prompt traps
Vagueness — a super-broad question covers everything and lands nowhere. Bias — these models are people pleasers; a leading question gets confident agreement with its flawed premise (sycophancy), the most visible source of made-up answers. Overload — plan a business + marketing strategy + website copy in one prompt usually returns three short lists, nothing you could act on. Spotting the trap skips the wasted round-trips.
Tokens and next-token prediction
An LLM is trained on huge text corpora and handles language by breaking it into tokens (a word may be one token; longer words split into several). Generation is a repeated calculation: out of a vocabulary of tens of thousands of English tokens, predict the most likely next, then repeat — which is why answers stream word by word. Clean input steers that prediction; messy input hands the model half-usable pieces.
Hallucinations and sycophancy
A hallucination is confident output that is not true — the model writes token by token with best guesses, so vague or unsupported prompts get convincing gaps filled. The people-pleaser effect makes it continue a shaky framing instead of correcting it (“why did the author say this quote?” and it invents the story). Modern models reduce both, but on specific or subjective topics the risk stays.
Context windows and chunking
Context = everything the model sees at generation: your prompt, the chat history, system instructions — the app re-sends all of it every turn because the core model remembers nothing. The context window is finite; past it, input is dropped or ignored, and very large prompts weaken answers even earlier. Fix: chunk the job into sequential prompts (summarize the report, then draft the email from that summary, then the captions), keep instructions ordered with the important parts first, and one task per turn.
Efficiency, cost, and monitoring
Every API call bills per token — input plus output; wasted politeness and long preambles are real money at scale (the course cites the Altman quip that pleasantries cost tens of millions). Levers: skip preambles and overlapping instructions, cap output length, request bullet lists or tables, ask for a summary first. Providers expose token dashboards; open-source observability tools like PromptLayer, Langfuse, Helicone add monitoring; smart caching answers repeats without a model call. Treat prompt performance like a product feature and A/B test it.
The Act-as hack and the prompt formula
Make the model adopt a professional role (“act as a graduate student writing a thesis on renewable energy”) — tone, detail level, and perspective shift with it, and open-source collections of hundreds of ready-made “act as” prompts exist for inspiration. Generalize it into the reusable formula: role (perspective), task (what to do), style (how it reads), constraints (length, time, budget, format) — fall back on it whenever you are stuck.
Iterative refinement and prompt chaining
Refinement means shaping output step by step instead of demanding perfection on try one: one adjustment per round, specific each time, and reuse earlier answers as raw material so the model works with context instead of restarting. Decide deliberately when to continue a thread versus open a new chat (misleading history wastes tokens). Chaining: ask one model for a detailed, professional-grade prompt (for an image generator or any specialized tool), then feed that prompt to the executor — one AI acts as the prompt engineer, another delivers.
Debugging prompts: isolate – adjust – self-correct
When a result is wrong, don’t rewrite everything (that multiplies variables). 1. Isolate: if the prompt holds five instructions, drop four — did the one key task work? Then the problem is overload or conflicting instructions; if even that fails, it is misinterpretation or a context problem (check what hit the window). 2. Adjust: temperature is the creativity dial of enterprise APIs — low = safe, predictable, factual; high = varied, imaginative, risky. No dial in a web app? Substitute with metaprompting (“entirely factual, no speculation” vs “be imaginative and produce three varied options”). 3. Self-correct: ask for the plan first (list the steps and the critical data before the final answer), and challenge a failed output — name what it ignored, ask it to analyze where it went wrong and regenerate.
Chain of Thought vs ReAct
Chain of Thought: direct the model to think step-by-step (or select a reasoning-capable model in the API) — reliable results when multiple steps matter: math, logic puzzles, abstract reasoning; overkill for a single fact. ReAct = reasoning + acting: the model alternates writing its thought (“I need the Q2 report”), taking an action (search, read a document, run code), and reading the observation before the next move. Use CoT when careful reasoning alone suffices; use ReAct when the task also needs fresh external information or execution — otherwise CoT alone guesses from stale training data.
Agents and the ReAct loop
An AI agent is an LLM whose system prompt enforces an iterative plan-act-observe loop — ReAct is the blueprint. The template: Thought (analyze the question, state what external information is required) → Action (select one tool/query/calculation — the framework around the model executes it) → Observation (evaluate the tool result) → repeat until confirmed, then answer from all observations. Benefits: parseable output (fixed action syntax), fewer hallucinations (facts from tools, citations required), and dynamic context — each observation refreshes what the model sees.
Image and video prompting
Generation prompts matter even more than text ones and follow subject + style + environment + parameters. MidJourney’s syntax is the clearest example of parameterized control — --ar (aspect ratio), --seed (reproducibility), stylize (artistic intensity), --chaos (artistic variation) — categorized as technical vs creative parameters. Practical loop: generate several cheap variations (about four), pick, then upscale or vary before spending on a high-quality render. Add negative prompts for what to avoid, reference artists/mediums/genres (style calling), study prompt galleries, and use reverse image prompting — upload a picture and get back the prompt that would have created it. Conversational generators accept the same controls in plain language, and the identical formula plus movement powers video models (Sora, Veo, Firefly video).
Coding assistants
Treat the prompt as a complete instruction set, and the assistant as a fast partner, not a replacement for QA. Always attach the relevant files (in ask-mode especially) — forcing the model to deduce context wastes reasoning tokens; give images directly for UI work (visual context beats a prose description); store multi-step instructions as prompt files. Safety nets for sweeping agent edits: Git (revert fast, explore branches) plus a final human code review before merging even when tests pass. For build errors, let the agent run the build so both of you see the exact compile errors. Mind premium-request quotas (one prompt ≈ one request — simple one-file questions belong in free chat), and switch models after a few failed attempts — no single LLM wins all tasks.
Enterprise API practice
Deployed via API, prompts must also be efficient and robust: be brutally concise (bullets, abbreviations), and cut output cost with max_tokens-style settings plus instructions (“respond in under 50 words”). Model routing — design instructions for the smallest reliable model and reserve high-reasoning models for complex analysis. Downstream systems need structured output: “respond only as a valid JSON object” / a given XML schema, with few-shot examples to lock formats (dates, fields). Production discipline: cache and reuse identical prompts/responses, enforce determinism (low temperature, fixed seeds where supported so users don’t get different answers), version prompts like code (Git, staging-test before rollout), log telemetry (cost, latency, failure rates — Langfuse/PromptLayer or dashboards), and never send sensitive user data raw — anonymize or hash.
Bias, ethics, and the three-layer guardrails
LLMs mirror the historical bias in their training data: representation bias (a medical model trained only on adults misses child-disease patterns), confirmation bias (the trained-in stereotype — CEO imagery skewing heavily one direction), cultural bias (a “wedding” prompt defaulting to one culture’s norms). Case study: Amazon’s experimental recruiting tool, trained on ten years of male-dominated hiring data, penalized résumés containing “women’s” — an efficiency success that scaled human bias. Failure modes: malicious prompt injection/jailbreaking, but also the quieter faithful reproduction of embedded bias. Defense is a three-layer system: (1) the vendor foundation — safety rules built in via RLHF and the model’s specification (system rules override developer and user prompts; OpenAI publishes its model spec), (2) a context firewall — a filtering agent that masks PII and removes profanity from data before it reaches the model (critical with RAG), (3) a bias buffer — prompt design that actively requests diverse representation. Add red teaming: an attack team probes for harmful outputs while the defense fixes them. Guardrails make the model refuse gracefully — not an optional nicety, part of the architecture.
Closing principles
The field keeps expanding into multimodal models and agents, and safety must evolve with it — treat guardrail prompts like mission-critical code, continuously validated. Three core principles from the course: a good prompt is clear; a professional prompt is constrained (defined roles, JSON formats, explicit negative constraints); and architect for success with patterns like Chain of Thought and frameworks like RAG for multi-step, tool-using workflows — with safety first: guardrail system prompts enforcing ethics against injection and historical bias.
