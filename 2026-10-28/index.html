Summary

  • Relational mechanics — data lives in tables of rows (tuples/records) and columns (attributes, sometimes called domains); relationships are defined across those collections of rows with unique keys — a primary key identifies each row, a foreign key carries another table's key in so the two can be read as one picture.
  • Amazon RDS — the managed relational service: engines MySQL, PostgreSQL, MariaDB, SQL Server and Oracle (bring-your-own-license); AWS handles the server underneath — maintenance, health monitoring, old-hardware retirement — while you run the database. Free tier: the first 12 months, 750 hours/month of single-AZ micro classes (t2/t3/t4g.micro), 20 GB SSD storage and 20 GB of backups and snapshots.
  • RDS hands-on — Easy create (less say in access) vs Standard create; templates Production / Dev and test / Free tier; leave public access OFF; a multi-AZ cluster spreads databases across AZs so one zone failing doesn't sink the store; connect from an EC2 instance over the endpoint: mysql -h <endpoint> -P 3306 -u admin -p.
  • The NoSQL trio and DynamoDB — key-value, document stores (a running catalog of JSON-like documents, flexible schema) and graph (relationships between data entities — Amazon Neptune); DynamoDB's primary key splits into partition key + sort key with attributes alongside; its free tier is always free: 25 GB storage, 25 read and 25 write capacity units. Tables: Standard vs Standard-IA class, provisioned vs on-demand capacity, auto scaling at a ~70% utilization target.
  • Choosing between them — relational: normalized data, strict schema, tables joined by primary/foreign keys, tighter access control, table locks on edits, hourly instance pricing (+ engine, storage, backups); non-relational: flexible model tolerating holes and unstructured data, simple design, horizontal scaling, no lock-on-write, per-capacity-unit pricing; either way — keep a snapshot in the wings before you change anything.
  • Beyond the pair — Amazon Aurora (AWS-proprietary, MySQL/PostgreSQL-compatible: up to 5x performance, 15 read replicas, distributed storage — trade-off: locked to AWS); migration with AWS DMS and SCT (continuous replication for minimal downtime; SCT converts schemas plus stored procedures, functions and views); in-memory: ElastiCache as the managed cache vs MemoryDB for Redis — the Redis-compatible, durable, multi-AZ in-memory database.

Main concepts

Relational databases
Data organized in tables of rows and columns: a table is a grouping of related information; attributes are its named, typed columns (sometimes called domains), tuples — records or rows — are the basic units of data inside it. The relational part: relationships are defined between collections of rows, with unique keys keeping the data together.
Primary vs foreign keys
A primary key uniquely identifies every row of its table (a CustomerID on a customers table, an OrderID on an orders table). A foreign key drops another table's primary key into a combining table — that is how an orders-and-customers view is built from two separate tables, so the whole picture lives in one place.
Amazon RDS
Relational Database Service — AWS's main relational offering. Engines: MySQL, PostgreSQL, MariaDB, SQL Server, and Oracle (that one bring-your-own-license: buy it from Oracle, bring it to AWS). Being managed means AWS runs the underlying server work — maintenance, monitoring health, retiring and replacing hardware — while you manage the database itself.
RDS free tier
On a new account: the first 12 months of RDS free — 750 hours per month across three micro, single-availability-zone classes (t2.micro, t3.micro, t4g.micro), plus 20 GB SSD storage and 20 GB of backups and snapshots. The free-tier template also only builds a singular database — no multi-AZ cluster.
Templates and multi-AZ
Create-time templates: Production (the real thing), Dev and test (a copy to prove new things on) and Free tier. A multi-AZ cluster keeps databases in different availability zones — if one zone has a problem (say Virginia or Ohio), the database survives it instead of becoming a single point of failure.
RDS settings that matter
Database instance identifier + admin username (AWS recommends Secrets Manager for credentials); storage such as 20 GB on gp2 SSD; connect it to EC2 compute in the same VPC — the console can even build the subnet groups; public access: leave it OFF (don't let strangers find your database); security groups, and tags to record whose project the instance serves; authentication by password, IAM, or Kerberos; Enhanced monitoring adds useful metrics for a little extra cost.
Connecting from EC2
The RDS endpoint on the database details page is the host; for MySQL the client call is mysql -h <endpoint> -P 3306 -u admin -p — port 3306, user admin, password prompt. That is the whole bridge from an EC2 instance into the database.
The NoSQL trio
Three non-relational styles: graph databases — AWS describes them as a systematic collection of data emphasizing the relationships between data entities; document stores — a running catalog of JSON-like documents, flexible schema (the rules of what you can store), easy development, and scale-friendly at any size; and key-value stores.
Key-value databases
Each item pairs a primary key + attributes — the primary key splitting into partition key and sort key (the attributes describe the item; e.g. product ID + type, descriptors alongside). DynamoDB is AWS's key-value service; versatile workloads include social-media data, high-volume event feeds, compliance records and real-time analytics like click streams. DynamoDB's free tier is always free (no first-year window): 25 GB storage, 25 write + 25 read capacity units.
Building a DynamoDB table
Console: Create table → name, partition key (e.g. a number), sort key (e.g. a string) → defaults cover most tables. Items get created under their keys; item ordering follows the table's keys.
Table classes and capacity
Standard class is the recommended default; Standard-IA suits infrequently accessed tables — cheaper, but not for regular reads. Provisioned capacity prices a known read/write rate (auto scaling: adjustable min/max, scale-out when utilization nears 70%) — predictable; on-demand pays per request as it comes — flexible, more expensive per unit. Deletion protection guards against accidental deletes.
Scan vs query
A Scan returns every item in the table; a Query selects items for one partition key value, optionally pinned by a sort key condition. Pick query when a key is known; scan when you truly want it all.
Choosing between them
Relational: normalized storage with a fixed structure, tables joined by primary/foreign keys, standardized data, tighter security behind specific logins, and updates propagating through linked tables — at the cost of table locks on edits and the weak fit for horizontal scaling. Non-relational: flexible data models (missing fields fine), unstructured and semi-structured data, simpler designs, horizontal scaling, no lock-on-write and higher performance ceilings. Pricing matches: RDS bills a hourly instance price (engine affects it) + storage + backups; DynamoDB bills capacity units + table class + storage. Constant either way: take a snapshot/backup before you change anything.
Use-case mapping
Organizing customers + inventory + orders so shipments reach the right people → relational. A televised tournament — extreme concurrent read/write volume, dashboards everywhere, missing data tolerated → NoSQL: auto scaling takes the pressure spikes, the flexible schema rides through gaps in competitor feeds.
Amazon Aurora
An AWS-proprietary member of the RDS family for cloud-native applications, compatible with MySQL and PostgreSQL. Distributed storage system — parallel processing, more efficient data management, simpler clustering and replication; more up-front configuration. Up to 5x standard performance at scale, 15 read replicas, managed backups. Weigh against: only those two engines, limited customization and tooling, and lock-in — the data is not realistically portable off AWS.
AWS DMS
Database Migration Service — the few-click mover: sources include Oracle, MySQL, PostgreSQL and SQL Server; no drivers or applications to install and no changes to the source in most cases. Continuous replication keeps the source live → minimal downtime; self-healing (restarts after interruption, Multi-AZ for availability). Homogeneous = same engine both ends; heterogeneous = different engines (Oracle → Aurora). Fits: platform migrations, consolidation of many databases into one, ongoing replication for disaster recovery, feeding Redshift warehouses, and decommissioning on-prem data centers.
AWS SCT
Schema Conversion Tool — converts the source schema (the blueprint of how the database is constructed) into a format the target AWS database can use, and converts the code: stored procedures, functions and views. It flags the friction points: incompatible data types and features the target doesn't support. SCT rearranges the language; DMS then moves the data.
In-memory: ElastiCache vs MemoryDB
In-memory databases keep data in RAM instead of disk — far faster reads and writes for real-time needs. ElastiCache: a fully managed in-memory data store and cache service. MemoryDB for Redis: the Redis-compatible, durable in-memory database — the entire dataset in memory (more than 13 trillion requests/day, peaks of 160 million requests/second), automatically replicated across multiple AZs, persistent even through node failure. Workloads: web caching, real-time analytics on streams, session stores, gaming leaderboards, geospatial indexes.

True / false — quick round

Pick your answer — it highlights green (correct) or red (wrong) and the explanation appears immediately.

In relational tables, attributes are the rows and tuples are the columns.

False — attributes are the typed columns (sometimes called domains) and tuples are the rows/records.

A relational database defines relationships between collections of rows using unique keys.

True — that is the defining relational move.

A foreign key is another table's primary key placed into a target table so data links together.

True — that reference is what lets two tables be read as one picture.

RDS's managed part covers maintenance, server-health monitoring and hardware retirement.

True — AWS handles the server; you handle the database.

Every RDS engine is fully licensed by AWS — nothing extra to buy.

False — Oracle on RDS is bring-your-own-license: buy it from Oracle, bring it to AWS.

The RDS free tier applies to the first 12 months of the account.

True — a first-12-months benefit.

The RDS free tier covers 750 hours/month of single-AZ micro classes, 20 GB SSD and 20 GB of backups.

True — t2/t3/t4g.micro at 750 h/month plus the storage and backup allowances.

The free-tier template provisions a multi-AZ cluster by default.

False — the free tier builds a singular single-AZ database; there is no multi-AZ safety there.

A multi-AZ database cluster keeps serving when one availability zone has a problem.

True — databases in different AZs remove the single point of failure.

DynamoDB's free tier stays free beyond an account's first year.

True — always free: no 12-month window on 25 GB / 25 RCU / 25 WCU.

Standard-IA is the recommended default DynamoDB table class.

False — Standard is the recommended default; Standard-IA trades regular reads for cost.

On-demand capacity always costs less than provisioned capacity.

False — on-demand pays per request for flexibility and costs more per unit; provisioned prices the known rate.

DynamoDB auto scaling holds before adding capacity until utilization nears ~70%.

True — scale-out fires around the 70% utilization target.

A Scan is the efficient way to fetch one partition key's items.

False — Scan returns every item in the table; Query targets a partition key (+ sort key).

Relational databases want normalized, structured data; non-relational tolerate holes and unstructured data.

True — the structure-vs-flexibility split.

Non-relational databases require identical fixed fields in every record.

False — a flexible data model is their point; missing pieces don't break them.

Editing one item in a relational table never affects anything linked to it.

False — updates propagate through the linked tables, and edits can lock them meanwhile: linked consistency is relational strength and friction at once.

Relational database pricing is dominated by per-request read/write units.

False — that is DynamoDB's unit (RCU/WCU); relational bills hourly instances plus engines, storage and backups.

A normalized customers/inventory/orders store is a natural NoSQL fit.

False — linked structured records needing consistent joins are the classic relational (RDS) case.

DynamoDB's rigid schema makes high-volume tournament dashboards impractical.

False — auto scaling takes the spike and the flexible schema tolerates missing feeds: the tournament case is a DynamoDB fit.

Aurora offers up to 5x standard performance and up to 15 read replicas.

True — Aurora's headline numbers.

Aurora keeps your data easily portable to other providers.

False — proprietary means lock-in: moving that data elsewhere is not really feasible.

Aurora supports only MySQL and PostgreSQL as its two engines.

True — two engines, not the wider RDS set.

RDS offers fewer engine choices than Aurora.

False — RDS's six engines and its customization options are exactly the edge over Aurora.

Aurora's performance metric reporting is simpler than plain RDS's.

False — it's the reverse: plain RDS provides performance metric reports a little more simply.

In-memory databases store data in RAM rather than on disk, for far faster access.

True — RAM-backed reads and writes are the speed story.

ElastiCache is the managed in-memory cache service; MemoryDB is the Redis-compatible durable in-memory database.

True — cache service vs durable database, same RAM idea, different guarantees.

MemoryDB replicates data across multiple AZs and survives a node failure.

True — durability is the point of MemoryDB for Redis.

DMS requires installing drivers on the source database before a migration.

False — DMS needs no drivers/applications and no source changes in most cases.

DMS supports both homogeneous and heterogeneous migrations.

True — same-engine and cross-engine moves.

The RDS endpoint is the host the mysql client connects to from an EC2 instance.

True — endpoint + port 3306 + admin + password prompt.

A DynamoDB table's schema is declared once at creation and can never be varied.

False — DynamoDB's flexible model allows different types of data and holes in it, at any scale.

Standard is the recommended DynamoDB table class for normal workloads.

True — Standard-IA is the variant, for infrequently-accessed tables.

A Query can narrow items with a sort-key condition once the partition key is fixed.

True — partition key first, then the sort key condition.

Nothing can stop a DynamoDB table from being deleted in an accident.

False — deletion protection is a toggle for exactly that.

DMS keeps the source database operational during migration through continuous replication.

True — source stays live, downtime stays minimal.

SCT handles only table definitions; stored procedures must be rewritten by hand.

False — SCT converts stored procedures, functions and views too, and flags incompatible types.

MemoryDB can serve over 13 trillion requests a day with peaks of 160 million per second.

True — MemoryDB's scale numbers, dataset entirely in memory.

MemoryDB keeps its dataset primarily on disk with a RAM cache in front.

False — the entire dataset lives in memory; replication across AZs provides the durability.

Session stores and gaming leaderboards are classic relational workloads.

False — they are classic in-memory/NoSQL workloads (MemoryDB, DynamoDB): microsecond, high-concurrency access.

Quizzes

1. Which AWS service is the managed relational database offering, and what does “managed” cover?

Show answer
Amazon RDS. Managed = AWS handles the server underneath: maintenance, health monitoring, hardware retirement — you run only the database layer.

2. Name the RDS engines; which one works differently to license?

Show answer
MySQL, PostgreSQL, MariaDB, SQL Server, and Oracle — Oracle is bring-your-own-license (buy the license, bring it to AWS).

3. What does the RDS free tier grant, and for how long?

Show answer
The first 12 months: 750 hours/month of single-AZ micro classes (t2/micro/t3.micro/t4g.micro), 20 GB SSD storage, and 20 GB of backups and snapshots.

4. What's a foreign key, functionally?

Show answer
Another table's primary key referenced inside a target table — it lets rows from two tables combine into one clear picture (an orders view over customers + orders).

5. Name the three NoSQL styles and AWS's main key-value service.

Show answer
Graph (relationships between entities — Neptune), document stores (JSON-like, flexible schema), and key-value — run by DynamoDB on AWS.

6. What two pieces make up a DynamoDB primary key?

Show answer
The partition key and the sort key; the item's attributes live alongside them.

7. When does a Scan make sense instead of a Query?

Show answer
Only when you actually want every item — Query can target a specific partition key (optionally with a sort key condition), Scan cannot.

8. During an Oracle → Aurora migration, which tool converts the code and which moves the data?

Show answer
SCT converts the schema plus stored procedures, functions and views (flagging incompatible types); DMS then replicates the data with minimal downtime.

9. Homogeneous vs heterogeneous in DMS terms?

Show answer
Homogeneous = the same database engine on both ends; heterogeneous = different engines (the Oracle → Aurora case).

10. One line: ElastiCache vs MemoryDB?

Show answer
ElastiCache = fully managed in-memory data store and cache; MemoryDB for Redis = the Redis-compatible durable in-memory database, replicated across AZs.

1. An online store must keep customers, inventory and orders consistent and always route shipments to the right person. Which database shape — and why?

Show answer
Relational (Amazon RDS): normalized tables for customers/inventory/orders, joined by primary and foreign keys so one combined table drives the shipping decisions.

2. You run a live televised tournament: thousands of concurrent score writes, dashboards across websites, occasional missing feeds. Pick the technology.

Show answer
DynamoDB (NoSQL): auto scaling absorbs the spike, the flexible schema tolerates the gaps, dashboards stream off real-time reads.

3. Your mobile app's session data must be answered in microseconds, survive the loss of a node, and never depend on one AZ. What runs it?

Show answer
MemoryDB for Redis: the whole dataset in RAM, replicated across multiple AZs, persistence through node failure.

4. An on-prem MySQL database must be on AWS with the source staying live until cutover. What does the move?

Show answer
AWS DMS: continuous replication keeps the source operational → minimal downtime; no driver installs or source changes in most cases.

5. The same source is Oracle with years of stored procedures, heading to Aurora. Who handles what?

Show answer
SCT converts the schema AND the stored procedures/functions/views, flagging incompatible types; then DMS performs the heterogeneous data migration.

6. Eight small databases of mixed engines, one data-center decommissioning ahead. What's the plan?

Show answer
DMS: consolidate the set into a single AWS target database, ongoing replication for the transition, then retire the physical data center.

7. A write-heavy table has predictable traffic all month. Which DynamoDB capacity mode — and why?

Show answer
Provisioned (with auto scaling): the known RCU/WCU rate prices predictably and per-unit beats on-demand for steady workloads.

8. A production schema change is scheduled. What must already exist?

Show answer
A snapshot/backup — keep at least one in the wings before changing either database type.

Pick the database — service selection drill

For each workload, pick the service that fits best — first try counts.

An online store: customers, inventory and orders must join into consistent rows that drive shipping. First service to reach for:

Structured, linked, normalized records over several tables — relational is the fit; RDS is the managed relational service.

A global event feed: thousands of writes a second, missing fields tolerated, dashboards live-updating. Pick:

High-volume, flexible-schema, horizontally-scaled reads and writes — DynamoDB.

A gaming session store: microsecond access, survives the loss of a node, copied across AZs. Pick:

Durable in-memory with multi-AZ replication = MemoryDB for Redis; ElastiCache is the cache, not the durable store.

On-prem Oracle must land on AWS with minimal downtime, source live to the last moment. Pick:

DMS continuously replicates so the source stays operational — minimal downtime is its calling card.

Years of stored procedures, functions and views must speak AWS before data moves. Pick:

Schema AND code conversion — stored procedures, functions, views — with incompatible types flagged: SCT.

A cloud-native app wants MySQL-compatible calls at up to 5x performance with 15 read replicas. Pick:

Aurora: up to 5x performance, up to 15 read replicas, MySQL/PostgreSQL-compatible — accepting its AWS lock-in.

A bursty read-cache in front of a web app; transient data, no durability requirement. Pick:

Caching-only, transient: ElastiCache — the managed in-memory store and cache; durability would push you to MemoryDB.

Traffic is unpredictable; you refuse to pre-commit a capacity rate. Which DynamoDB mode?

On-demand pays per request as it comes — the mode for unpredictable traffic (pricier per unit, no commitment).

Complex queries and transactions over strict, linked tables; hourly billing accepted. Pick:

Transactional, complex-query, normalized work is relational — hourly-instance RDS.

Fraud detection over heavily interconnected entities — relationships ARE the data. Pick:

Relationship-centric data is the graph case — Amazon Neptune (fraud detection, recommendations).
