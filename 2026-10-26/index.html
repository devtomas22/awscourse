Day 2026-10-26 · S3 and Storage

Pluralsight: AWS CLF-C02 — the Storage Technology and Services module: EC2 storage (EBS, EFS, instance store), Amazon S3 and its storage classes, the EBS deep dive, Storage Gateway and AWS Backup.

Day 4Topic: S3 & StorageSource: Pluralsight + class notes

Summary

Today was the S3 and Storage day — the Storage Technology and Services module (AWS CLF-C02):

  • EC2 storage trio — EBS, the persistent block volumes attached to your instances; EFS, the shared file system that scales automatically and serves many instances at once; instance store, free, high-I/O — but wiped the moment the instance stops, terminates, or crashes.
  • Amazon S3 — object storage in buckets (globally unique names) holding objects = data + key + metadata; designed for 11 nines of durability, protected by bucket policies and ACLs, and versatile enough for backups, static websites, CloudFront delivery, and big-data sets.
  • Storage classes — a cost ladder from S3 Standard (frequent, low latency) through Intelligent-Tiering, Standard-IA, One Zone-IA, and the three Glacier archive tiers — matched to access patterns: milliseconds for Glacier Instant Retrieval, up to 12 hours for Deep Archive.
  • Hands-on S3 — create a bucket, enable versioning to recover past objects, note that encryption is on by default and the defaults block all public access (deny unless explicitly allowed); bucket policy vs IAM policy; lifecycle rules transition objects between classes automatically.
  • EBS deep dive — SSD-backed volumes for high IOPS, HDD-backed for throughput (gp2/gp3, io1/io2, io2 Block Express, st1, sc1); Multi-Attach only for Provisioned IOPS SSD in one AZ; snapshots are incremental, shareable, and copyable across regions.
  • Storage ecosystem — Storage Gateway (S3 File, Volume, Tape, FSx File gateways) bridges on-premises to cloud; AWS Backup centralizes policies and cross-region/account backups; FSx serves native Windows file systems and Elastic Disaster Recovery keeps business running when infrastructure fails.

Main concepts

The EC2 storage trio — EBS vs EFS vs instance store
EBS = persistent block storage attached to one instance at a time — data survives a crash or stop. EFS = a shared file system many instances use concurrently. The instance store = ephemeral block storage physically attached to the instance — blazing fast I/O, but gone when the instance stops, terminates, or crashes, and included at no extra cost.
Amazon EBS
Persistent block-level storage volumes for EC2. Data remains intact even after stopping the instance; volume data is automatically replicated within its availability zone; volumes are resizable on the fly without downtime; encrypted in transit and at rest; snapshots provide backup and recovery. Use cases: relational/NoSQL databases, data warehouses and big-data analytics, ERP and CRM apps.
Amazon EFS
Elastic File System is scalable file storage for EC2 and other AWS services. Fully managed, scales up and down automatically as files come and go (you pay only for what you use), and is built for concurrent access from many instances simultaneously. Fits content management, web serving, big-data analytics, and dev/test/staging environments.
Instance store
Temporary block-level storage directly attached to the instance. Attributes: high I/O performance from the direct attachment; ephemeral — data is lost if the instance stops, terminates, or crashes; no extra cost — part of the instance price. Best for caches, buffers, write-heavy-and-discard workloads, and data replicated across instances (distributed processing).
Amazon S3 — object storage, the bigger picture
S3 is globally accessible object storage — the cloud's default place to park data, reachable from anywhere. The bucket is the primary container; inside it live objects — each is data plus a key (unique within the bucket) plus metadata. Durability is designed at 11 nines over a year; it scales to any data volume; security via bucket policies and access control lists; versatile enough for backup, static websites, CloudFront content delivery, and big-data storage.
S3 security — bucket policy vs ACL vs IAM policy
A bucket policy controls permissions for any user to access the bucket's objects. ACLs manage access to buckets and objects. For a specific user, you go to the IAM console and control it through IAM policies. AWS defaults to a deny-all: if nothing explicitly allows the action, it's denied — and new buckets by default block all public access.
Versioning and lifecycle policies
Versioning keeps previous versions of an object — after an unintended edit, download the earlier version and re-upload it; it's toggled per bucket at creation. Lifecycle rules automate actions on groups of objects — most commonly transitioning storage classes (e.g. Standard → Glacier) or deleting objects, which is the cost-optimization lever.
S3 storage classes
Seven rungs on the ladder: S3 Standard (frequent access, high throughput, low latency, data spread over multiple devices and facilities), Intelligent-Tiering (unpredictable patterns — auto-moves between two tiers), Standard-IA (rare but rapid access — retrieval fee), One Zone-IA (single AZ, cheaper, less durable — reproducible/secondary data), Glacier Instant Retrieval (archive, millisecond retrieval), Glacier Flexible Retrieval (1–2 times a year, free large retrievals), Glacier Deep Archive (cheapest, retrieval up to 12 hours, 7–10+ year regulatory retention).
EBS volume types — SSD vs HDD
Two families. SSD-backed = transactional workloads with frequent small read/writes and quick responses — high IOPS (operations per second). General Purpose (gp3/gp2) for transactions, virtual desktops, low-latency interactive apps, dev/test; Provisioned IOPS (io1/io2) for sustained IOPS and sub-millisecond latency — up to 64,000 IOPS/volume, io2 Block Express up to 256,000. HDD-backed = throughput (bits/bytes per second, large streaming transfers): st1 for big data/warehouses/logs, sc1 for infrequently accessed data at lowest cost.
EBS Multi-Attach
Attaches a single Provisioned IOPS SSD volume to multiple instances in the same availability zone. Not supported on HDD volumes — a classic exam differentiator.
EBS snapshots
Point-in-time volume backups that are incremental — each snapshot stores only the block-level changes since the last one, keeping them cost-effective. From a snapshot you can restore a volume or launch a new instance with the data; snapshots can be shared with other accounts or made public, and copied across regions for disaster recovery.
AWS Storage Gateway
The hybrid bridge: connects on-premises storage to AWS. Cost-efficient (less on-prem hardware), secure (encrypts data for transfer and storage), integrates with existing apps. Four types: S3 File Gateway (files stored directly on S3 in cloud-native formats), Volume Gateway (block volumes backed by S3 — stored volumes keep the full dataset on-prem, cached volumes keep frequent data in AWS), Tape Gateway (archives as virtual tapes), FSx File Gateway (extends on-prem file systems to FSx for Windows File Server). Use cases: backups, disaster recovery, processing data in AWS.
AWS Backup
A centralized service to configure backup policies and monitor backup activity across AWS. Covers EC2 instances, EBS volumes, RDS databases, DynamoDB tables, EFS file systems, FSx file systems, and Storage Gateway volumes. Features: centralized management, automated backup scheduling via policies, encryption and compliance, cross-region and cross-account backups for disaster recovery. Recovery is straightforward — restore quickly with minimal downtime.
Specialized storage — FSx and Elastic Disaster Recovery
Amazon FSx: a fully managed Windows file system for Windows-native workloads — seamless integration, reliability, scalability. Elastic Disaster Recovery: the backup generator — minimizes downtime and data loss with swift recovery times and pay only for the servers actively replicating to AWS; about business continuity, not just backups.

Quizzes

1. Name the three EC2 storage options — one sentence each.

Show answer
EBS — persistent block storage attached to EC2. EFS — shared, elastic file system for many instances at once. Instance store — ephemeral, high-I/O storage included with the instance, wiped when it stops or is terminated.

2. Of what is an S3 object composed?

Show answer
The data itself, a key unique within the bucket, and metadata — stored inside a bucket whose name is globally unique.

3. How durable is S3, and what secures it?

Show answer
Designed for 11 nines of durability over a year; security comes from bucket policies and access control lists (plus IAM policies per user).

4. You can't predict when access spikes or drops. Which class?

Show answer
S3 Intelligent-Tiering — automatically moves objects between two access tiers; savings without performance impact.

5. Name the three Glacier classes and their retrieval profile.

Show answer
Instant Retrieval: milliseconds. Flexible Retrieval: 1-2 accesses a year, large retrievals free. Deep Archive: cheapest, up to 12-hour retrieval, 7-10+ year retention.

6. Bucket policy vs IAM policy for S3 — what's the difference?

Show answer
A bucket policy controls permissions for any user to access the bucket. An IAM policy controls a specific user's access, configured in the IAM console.

7. What do lifecycle policies automate, and why care?

Show answer
Transitioning objects between storage classes (e.g. Standard → Glacier) or deleting them — the standard tool for cutting storage cost.

8. List the four Storage Gateway types.

Show answer
S3 File Gateway (files on S3), Volume Gateway (block volumes backed by S3 — stored/cached), Tape Gateway (virtual tapes), FSx File Gateway (extends on-prem to FSx for Windows File Server).

9. Which resources can AWS Backup protect?

Show answer
EC2 instances, EBS volumes, RDS databases, DynamoDB tables, EFS file systems, FSx file systems, and Storage Gateway volumes — plus cross-region and cross-account copies.

10. Which EC2 storage is free with high I/O, and at what price?

Show answer
Instance store — no additional cost and fast direct-attached I/O; the price is permanence: data is gone if the instance stops, terminates, or crashes.

7. A platform team wants policy-driven, scheduled backups of EC2, RDS and DynamoDB with copies in another region.

AWS Backup — centralized policies, automated schedules, encryption/compliance, and cross-region/account backups.

8. A firm wants its Windows file shares in AWS without losing native Windows features.

Amazon FSx — the fully managed Windows file system built for Windows-specific workloads.
