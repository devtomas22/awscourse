Main concepts — the week by day

Storage · session 2026-10-26

The EC2 storage trio · Oct 26
EBS — block volumes attached to instances, persisting independently of the instance’s life. EFS — shared POSIX file system many instances mount at once across AZs, growing on demand. Instance store — ephemeral block storage on the host itself: fastest I/O, but gone on stop or termination.
S3 object storage: durability vs availability · Oct 26
S3 keeps unlimited objects in buckets with 99.999999999% (11-nines) durability — a durability target — while availability (ability to serve when asked) is a separate, lower, class-specific design figure. Writes are strongly read-after-write consistent. Security stacks per bucket: IAM (identity), bucket policy (resource), and (legacy) ACLs.
Storage classes and the fine print · Oct 26
Seven classes trade access cost for speed: Standard (hot) down to Glacier layers (archive). The fine print: 30/90/180-day minimum storage durations for IA and the Glacier tiers, a 128 KB minimum billable object on the cold tiers, and per-GB retrieval fees when you pull from them. Intelligent-Tiering tracks access patterns and moves objects between access tiers automatically — no retrieval fees, no operations.
Versioning, lifecycle and replication · Oct 26
Versioning keeps every write as a new version (deletes become deletion markers — recoverable data). Lifecycle rules transition objects between classes or expire them on a schedule. Replication copies objects asynchronously: CRR to another Region (compliance, lower latency for other users, DR) or SRR within the same Region (log aggregation, sync between environments).
S3 access hardening · Oct 26
Block Public Access rejects public access settings regardless of bucket policies, account- or bucket-wide. Presigned URLs hand out time-limited authorized GET/PUT links without sharing credentials. Encryption options: SSE-S3 (managed keys), SSE-KMS (AWS KMS keys + audit), SSE-C (client-supplied keys); EBS volumes and DynamoDB encrypt too.
EBS deep dive · Oct 26
Volume types split into SSD (transactional, IOPS) and HDD (throughput) families. gp3 decouples IOPS and throughput from capacity — tuning gp2 never could — usually at lower cost. Multi-Attach (io1/io2) attaches one volume to up to 16 instances within a single AZ. Snapshots are incremental and region-scoped; restore makes a fresh volume. Around them: Storage Gateway (hybrid), AWS Backup (central policy-based backup), FSx (specialized file systems), EFS modes, Elastic Disaster Recovery.

Networking · session 2026-10-27

VPC fundamentals · Oct 27
An Amazon VPC is your isolated, region-scoped network with a CIDR you choose. Inside it, the three networking zones separate concerns (public edge, private app tier, private data tier); subnets live inside one AZ each with public/private tiers per role; every subnet CIDR has five IPs reserved. DHCP option sets hand instances their domain name and DNS servers.
Routing the VPC · Oct 27
Route tables decide destinations (a local route connects all subnets by default). The internet gateway is the VPC’s edge to the internet. NAT gateways let private-subnet instances go out (updates, patches) while blocking unsolicited inbound — deployed in a public subnet, AZ-bound for HA with a cost note (hourly + per-GB data processing).
Security groups vs NACLs · Oct 27
Security groups are stateful, instance-level, allow-rules-only (default deny); they support cross-group rule sources (another SG as the source), so layered defense stays readable; return traffic needs no extra rule. NACLs are stateless, subnet-level, numbered allow/deny — and the ephemeral return-port trap bites anyone who rules only standard service ports.
VPC endpoints and PrivateLink · Oct 27
Gateway endpoints add routes for S3 and DynamoDB — no charge, no DNS change. Interface endpoints create per-AZ private IPs ( Elastic Network Interfaces) for many AWS services and third-party SaaS, billed hourly per AZ plus per GB; DNS resolves the service to them. PrivateLink lets you publish your own service to other VPCs privately.
DNS switches, Flow Logs and troubleshooting · Oct 27
Two attributes flip DNS behavior: enableDnsSupport (VPC needs AWS DNS) and enableDnsHostnames (public hostnames for instances) — both required together. VPC Flow Logs record accepted/rejected traffic for audit and debugging. When something is unreachable, work inside-out (routes → SG → NACL → endpoint); VPC Reachability Analyzer proves or disproves end-to-end paths without touching traffic. Beyond one account: VPC peering (non-transitive), Transit Gateway (hub-and-spoke at scale), site-to-site VPN (datacenter hybrid).

Databases · session 2026-10-28

Relational data and RDS · Oct 28
Tables with rows and schemas; primary keys identify rows, foreign keys tie tables with integrity. RDS runs five engines (MySQL, PostgreSQL, MariaDB, SQL Server, Oracle) with a 12-month free tier; templates and multi-AZ give a synchronous standby; connecting from EC2 means security-group plumbing and the connection string.
Read replicas vs multi-AZ; backups vs snapshots · Oct 28
Read replicas replicate asynchronously for read scaling (and you can promote one to a standalone DB for DR); multi-AZ replicates synchronously to a standby purely for failover — same writer endpoint stays. Automated backups enable point-in-time restore from transaction logs; manual snapshots persist until you delete them.
DynamoDB core · Oct 28
NoSQL key-value store at scale: each item needs a partition key (plus optional sort key) as its primary key; queries must address the partition key. Capacity modes: on-demand vs provisioned (RCU/WCU). Fine print: items cap at 400 KB; a capacity unit absorbs ~4 KB reads / 1 KB writes. Table classes trade storage price vs throughput price. Scan reads everything (expensive); query uses the keys.
DynamoDB extras: Streams, Global Tables, DAX · Oct 28
DynamoDB Streams — an ordered, near-real-time record of item-level changes (captured for triggers and pipelines). Global Tables — multi-Region active-active replicas for global low latency and DR. DAX — an in-memory cache in front of DynamoDB cutting read latency to microseconds.
Aurora storage and Serverless v2 · Oct 28
Aurora (MySQL/PostgreSQL-compatible) keeps six copies of data across three AZs, hides them behind writer and reader endpoints, and its distributed storage auto-grows to 128 TiB. Aurora Serverless v2 scales capacity in fine-grained steps (ACUs) instead of coarse instance-size jumps — matching load in real time.
Choosing, migrating, caching · Oct 28
RDS vs DynamoDB: schema/joins/locking vs flexible schema, horizontal scale and predictable key-based cost. Moving data: SCT converts schemas (heterogeneous engine→engine), DMS moves the data continuously with minimal downtime — either direction (also onto Aurora). ElastiCache vs MemoryDB for Redis: a cache in front of a database vs a durable primary database in its own right.

Costs · session 2026-10-29

The five cost drivers · Oct 29
Compute (instances and their hours — the single biggest line), storage (GB-months, class-dependent), databases (instance hours + storage + backup + I/O), data transfer (usually dominated by transfer out to the internet), and networking (load balancers, NAT processing, cross-region traffic). Each has its own levers; class, Region and sizing all move the bill.
The pricing trio · Oct 29
The free tier comes in three shapes: 12-month allowances, always-free services, short trials. Reserved Instances commit 1 or 3 years for up to 72% off on-demand — best for steady state. Savings Plans commit an hourly $ spend and stay flexible across families/OS. Spot rides spare capacity at steep discounts — interruptible, so only for fault-tolerant work.
Seeing the bill: Cost Explorer, Budgets, alerts · Oct 29
Cost Explorer visualizes and forecasts usage (roughly a year back, 18 months forward; grouping by service, tags, API… — but no forecast while grouped; hourly granularity is an opt-in; data refreshes on up to a 24-hour cadence, so it can differ from the invoice). Billing dashboards + cost-allocation tags attribute spend. Anomaly detection learns spend patterns and alerts on deviations. AWS Budgets tracks six budget types with free monitoring while budget-days stay low (then $0.02/day), the first two action-enabled budgets free, an 8–12-hour refresh cadence, actual-vs-forecast thresholds, and actions that stop EC2/RDS to enforce a cap.
The standing cost playbook · Oct 29
Five provisioning decisions shape the bill (OS/licensing, tenancy, size, family, purchase option). Right-sizing: Trusted Advisor and Compute Optimizer flag idle and oversized instances. Scale manually for steady load, automatically with spend caps for spikes. The six classic overspend scenarios — forgotten non-production instances, wrong-sized instances, idle EBS volumes and unneeded snapshots, cross-AZ/cross-Region chatter, unbounded log storage, and orphaned public IPs / NAT data processing — each have a matching mitigation.

Content delivery · session 2026-10-30

The CDN case and CloudFront · Oct 30
Content far away costs latency; the further the request travels, the more hops add delay — Amazon measured ~1% of sales lost per 100 ms. A CDN caches content close to users at points of presence. CloudFront is the AWS CDN: static and dynamic delivery, streaming and API acceleration, HTTPS everywhere, signed URLs/cookies, geo-restriction, and Shield + WAF + Route 53 co-located at the edge.
Edge network scale (2026) · Oct 30
Verified from AWS docs that same day: 750+ PoPs in 100+ cities across 50+ countries, 1,140+ embedded PoPs across 300+ cities deployed inside ISP networks themselves (closest to viewers, bypassing congested networks), and 15 regional edge caches within AWS Regions. Requests ride the redundant AWS backbone toward origins.
Cache layers and the miss path · Oct 30
A request lands at a PoP (picked by CloudFront’s DNS on distance/latency; the Host header maps to your distribution). Cache hit at the edge — served. Miss → regional edge cache (bigger cache, objects live longer, on by default, no extra charge). Still missing → optional Origin Shield, a central cache that consolidates origin fetches to as few as one request per object, also deduplicating other CDNs’ fetches. Then the origin.
Origins and locking them down · Oct 30
An origin is S3 or any HTTP backend (EC2, ALB/NLB, API Gateway, MediaPackage…). Distributions carry multiple origins; origin groups fail over primary → secondary. VPC origins reach ALB/NLB/EC2 in private subnets with no public path at all. OAC keeps S3 private: the bucket policy allows cloudfront.amazonaws.com with the distribution’s ARN as condition, and Sign requests (recommended of the three signing behaviors) has CloudFront SigV4-signing every fetch — direct URLs die.
Distributions, behaviors and the policy trio · Oct 30
The distribution is the delivery unit (origins, routing, protocols, WAF, price class, its cloudfront.net name). Cache behaviors match request path patterns to one origin each plus caching policies; the auto-created default behavior is the catch-all, processed last. Each behavior tunes three policies: cache-key (what defines the cache key), origin request (what reaches the origin), response header (what goes back to viewers).
Edge compute, freshness and paying for it · Oct 30
CloudFront Functions — sub-millisecond JS at viewer events, millions of req/s, 10 KB code, no network/body access. Lambda@Edge — Node/Python at all four events, up to 30 s and 10 GB on origin events, network + body access, code auto-replicated from one Region. Connection Functions (2026) — JS inside the mTLS handshake (cert validation, custom auth) before HTTP begins. Freshness: with no cache-control from the origin, edge objects re-check after 24 hours; the Invalidation API clears sooner (3,000 objects in progress, 15 wildcard paths). Pricing 2026: pay-as-you-go with a free tier (1 TB out + 10M requests + 2M functions), new flat-rate plans ($0 / $15 / $200 / $1,000, no overage), or the Security Savings Bundle (up to 30% off).

Quizzes

1. Storage: name the three EC2-adjacent storage types and what differentiates them.

Show answer
EBS — block volumes bound to instances, persisting beyond the instance. EFS — shared POSIX file system mounted by many instances across AZs. Instance store — ephemeral storage on the physical host, fastest but lost on stop.

2. Storage: which S3 feature keeps every historical version of an object, and what happens to a delete?

Show answer
Versioning. Once enabled, every write adds a version and a delete creates a deletion marker — the older versions remain and can be restored.

3. Networking: how do you patch a private-subnet instance without making it reachable from the internet?

Show answer
A NAT gateway in a public subnet: private instances initiate outbound connections through it; unsolicited inbound traffic from the internet still has no path in.

4. Networking: stateful vs stateless — which filter needs a return-traffic rule for ephemeral ports?

Show answer
NACLs — stateless, so return packets must match their own rules, including ephemeral port ranges. Security groups are stateful: replies to allowed connections flow without an extra rule.

5. Databases: read replicas or multi-AZ — which one buys failover, and which buys read throughput?

Show answer
Multi-AZ = a synchronous standby for failover (the writer endpoint moves). Read replicas = asynchronous copies adding read scaling; promotable to a standalone DB for disaster recovery.

6. Databases: which DynamoDB mechanisms serve change capture, global delivery, and read latency?

Show answer
Streams capture item-level changes near-real-time; Global Tables replicate active-active across Regions; DAX adds an in-memory cache cutting reads to microseconds.

7. Costs: which commit purchase covers steady-state compute at up to 72% off, and which keeps the discount flexible across instance sizes and OS?

Show answer
Reserved Instances reach up to 72% off for 1/3-year steady-state commitments; Savings Plans commit an hourly $ spend instead — flexible across families, sizes and OS.

8. Costs: which tool shows this month’s bill going off-pattern, and which sets a $100 alarm that can automatically stop runaway instances?

Show answer
Cost Explorer / Billing dashboards + anomaly detection surface off-pattern spend; AWS Budgets sets the $100 threshold (actual or forecast) and its actions stop EC2/RDS instances automatically.

9. Content delivery: name the caching layers a viewer’s request can be answered from, in order, before the origin is touched.

Show answer
Edge location (PoP) → regional edge cache → optional Origin Shield. Only on misses does the request travel to the next layer.

10. Content delivery: which edge-compute option runs inside the TLS handshake, and which two handle HTTP events?

Show answer
Connection Functions run inside the mTLS handshake (cert validation, custom auth). The HTTP-event pair: CloudFront Functions (sub-millisecond JS, viewer events) and Lambda@Edge (all four events, network + body access).

1. A media library’s older videos are rarely viewed but keep billing at S3 Standard rates; ops wants the spend down without a retrieval shock.

Show answer
Intelligent-Tiering (or a lifecycle to IA/Glacier): access tracking moves cold objects down automatically — Intelligent-Tiering with no retrieval fees and zero tuning. Mind the cold-class fine print: 30/90/180-day minimums, 128 KB minimum objects, per-GB retrieval.

2. A bursty rendering farm mounts one shared home directory; today the team syncs data to each instance’s ephemeral disk and loses files on stop.

Show answer
Move the working set to EFS — one POSIX file system all instances mount across AZs, growing on demand; instance-store workdirs stay disposable by design.

3. A S3-hosted site’s objects must not be downloadable by anyone hot-linking the bucket URL — only by paying site visitors.

Show answer
Two layers from the week: presigned URLs for time-limited private-object access, or CloudFront + OAC (bucket policy allows cloudfront.amazonaws.com with the distribution’s ARN; direct URLs die).

4. A database-tier instance must fetch OS patches and reach S3 — and stay unreachable from the internet.

Show answer
NAT gateway for general outbound, and a gateway VPC endpoint for the S3 route — free and private, never touching the internet gateway. Security groups admit only those paths.

5. An analytics dashboard overwhelms the production database with read queries during business hours.

Show answer
Add read replicas: asynchronous copies absorb the read load — the dashboard points at a replica endpoint; a replica is promotable if the primary ever fails.

6. An order service records every item change, and three downstream teams each built their own polling loop against the table.

Show answer
DynamoDB Streams: one ordered, near-real-time change feed for all consumers — the polling loops get retired.

7. Dev and staging environments run 24/7 at full size; nobody remembers why, and the bill grew 40% in a quarter.

Show answer
The right-sizing playbook: Trusted Advisor + Compute Optimizer findings, scheduled or auto scaling for off-hours, a spend cap with Budgets actions, lines attributed with cost-allocation tags in Cost Explorer.

8. A launch event goes viral; the origin web server’s connection limit breaks in under a minute and pages stall worldwide.

Show answer
Front it with CloudFront: connections are served from 750+ PoPs, and only cache misses reach the origin — multi-user scaling from the CDN use cases.

9. A movie release goes live; viewers on another continent still see the old trailer, and marketing demands a global fix right now.

Show answer
An invalidation on the affected paths clears every edge location before the TTL expires — with the in-progress limits (3,000 objects; 15 wildcard paths) in mind.

10. A global app needs session state shared across Regions with local-latency reads — and the data must survive an entire Region failing.

Show answer
DynamoDB Global Tables (active-active multi-Region replication for DR and local latency), with DAX in front where read latency must drop to microseconds.

Instance store rides the physical host: top I/O at the price of ephemerality — data is gone on stop.

A private subnet’s jobs write nightly to S3 — with the cheapest, most private possible path.

Gateway endpoints add a free route for S3/DynamoDB — no hourly AZ charge, traffic never leaves the VPC’s edge.

You sell an internal API to customers who must reach it from their own VPCs without any internet path.

PrivateLink publishes your service as an endpoint in the customer’s VPC — private reach, no internet.

Regional disaster: the primary is gone, but a running copy of the database must become the new primary within minutes.

Read replicas are promotable to standalone databases — the DR path; multi-AZ covers AZ failures, not Region failures.

SCT converts schemas between engines; DMS then moves the data continuously with minimal downtime.
